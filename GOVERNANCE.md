# Governance

topic.earth is intended to be stewarded by a Belgian ASBL (association sans but
lucratif) dedicated to open climate, Earth-system, and regional knowledge tools.

This file records project intent. It is not proof that the ASBL already exists
and does not replace formal statutes, board decisions, transfer agreements, or
legal advice.

## Mission

topic.earth should remain a public-interest project that helps people explore
climate systems, local initiatives, reliable sources, and AI-assisted topic
research without locking the commons into a private platform.

## Interim Stewardship

Until the ASBL is created, project stewardship may be handled by SmDeltArt or a
CAD-AI-Support umbrella only if that role is documented in writing.

Interim stewardship should keep a clean transfer path for:

- the `topic.earth` domain;
- the GitHub repository and organisation rights;
- Vercel project ownership and deployment settings;
- Cloudinary/media hosting accounts and asset manifests;
- trademark, logo, and visual identity files;
- API keys, service accounts, and operational secrets.

## Licensing Principles

- Source code and project documentation are licensed under
  `EUPL-1.2-or-later` unless a file states otherwise.
- Contributors should submit code and documentation they have the right to
  license under `EUPL-1.2-or-later`.
- Assets require separate provenance and licence records in
  [ASSET-LICENSES.md](ASSET-LICENSES.md).
- The `topic.earth` name, domain, logo, and visual identity are protected
  separately in [TRADEMARKS.md](TRADEMARKS.md).

## Decision Model

Before ASBL creation, major decisions should be written down in project docs or
issues. Major decisions include licence changes, ownership transfers, domain
changes, public launch, user-account features, data-retention choices, and
asset-licensing decisions.

After ASBL creation, the statutes and internal rules should define:

- membership and voting;
- board or administrator responsibilities;
- maintainer appointment and removal;
- conflict-of-interest handling;
- financial transparency;
- data protection responsibilities;
- how project assets can be sold, transferred, or licensed.

## Contribution Expectations

Contributors should:

- keep source and media provenance clear;
- avoid adding proprietary or unclear assets;
- preserve EUPL, notice, trademark, and attribution files;
- document AI-generated media prompts and source material;
- separate experimental work from public data and reviewed content.

## User And Community Protection

Future user accounts, comments, submissions, uploads, and regional locality
features should be designed with consent, moderation, abuse control, data
minimisation, and transparent review workflows before public launch.
